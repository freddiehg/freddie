# PathMut peel + complete (Here / Up)

Not done. Standalone. Prefactor for `invalidation.md`.

Every code block below is the implementation, not a sketch. The laserbeam items, the macros, the derive change, and the emitted expansion have been compile-checked against the real `laserbeam::PathMut` (depth-12 macro expansion, all peel values, the off-chain and route-enum negatives).

## What

The leave API is on the path values themselves. No wrapper type, no constructor:

```text
path.complete()                                // Here(path)
path.into_parent().complete()                  // Up(Here(parent))
path.into_parent().into_parent().complete()    // Up(Up(root))
```

Peel is laserbeam `PathMut::into_parent` on existing `Place::Path` values. `complete` is laserbeam's `Complete<A>` trait method; `A` is the origin's ascent, pinned by the dispatch return type. The ascent alias for every non-root node is emitted by `#[derive(Bind)]`; consumers handwrite nothing.

Runtime peel depth unifies to one return type. Parent matches once:

```rust
match child_leave {
    Doll::Here(path) => { /* path: child’s Place::Path */ }
    Doll::Up(rest) => { /* rest: Ascent(this node) */ }
}
```

`(Focus, A)` alone selects the nest constructor: a `Place::Path` type encodes its full ancestry; each step up is a structural suffix of the previous type; a focus type appears at most once in any ascent nest. `PathMut<N, PathMut<N, _>>` is still a different type from `PathMut<N, _>`, so `(Focus, A)` stays unambiguous, and the `Up` count is determined by the pair.

## Current state (what exists today)

`laserbeam/src/lib.rs` holds `PathMut` (`from_fn`, `get`, `get_mut`, `into_parent`), `Ascend`/`AscendMut` with per-depth impls generated by `ascend_impls!` over `ascend_nest!`/`ascend_up!`/`ascend_up_ref!`, invoked to depth 12. No `Doll`, no ascent types, no `Complete`.

`bind_macro/src/lib.rs` `expand()` emits four items per place node:

```rust
let place = place_impl(input, name)?;
let accumulate = accumulate_impl(input, name, &marker, &binds)?;
let dispatch = dispatch_impl(input, name, &marker, &binds)?;
let descend = descend_impl(input, name, &marker);
Ok(quote! {
    #place
    #accumulate
    #dispatch
    #descend
})
```

Consumers handwrite path aliases and reference them in `#[node(parent = …)]` (`bind/tests/common/mod.rs`, `mercury/src/state/mod.rs`):


## Change 1 — laserbeam: `Doll`, `Ascent`, `Complete`, per-depth impls

All of the following goes into `laserbeam/src/lib.rs`, below the `Ascend`/`AscendMut` machinery (the macros reuse `ascend_nest!`, so they sit after it).

```rust
/// Where an ascent stopped: at this path, or somewhere further up.
///
/// `complete` produces it and a parent matches it, one layer per path type on
/// the chain from the origin, origin outermost, the root path bare at the
/// bottom. No derives: paths are neither `Debug` nor `PartialEq`; consumers
/// destructure.
pub enum Doll<H, U> {
    Here(H),
    Up(U),
}

/// The doll nest an ascent from this path completes into, as a type-level
/// function of the path alone.
///
/// `Ascent(root) = root path` (bare), `Ascent(node) = Doll<node path, Ascent(parent)>`.
/// Structural, so the bind derive can name a node's ascent without knowing any
/// ancestor: `AscentOf<Self::Path>`. A route enum implements neither arm, so a
/// multi-parent node has no ascent, exactly as it has no `Ascend`.
pub trait Ascent {
    type Out;
}

impl<'a, R> Ascent for &'a mut R {
    type Out = &'a mut R;
}

impl<N, P: Ascent> Ascent for PathMut<N, P> {
    type Out = Doll<Self, P::Out>;
}

pub type AscentOf<P> = <P as Ascent>::Out;

/// Complete an ascent: wrap this path into the nest `A` at its chain position.
///
/// `A` is a type parameter, not an associated type, because one focus completes
/// into every ascent whose chain contains it (a `LayerPath` into `NavAscent`,
/// `TypingAscent`, and `LayerAscent`). The call site's expected type pins `A`;
/// inside a dispatch that is the return type, and anywhere else an annotation.
///
/// One impl per (origin depth, focus position), generated by `complete_impls!`
/// below, matching on the shape of the path rather than on which node it is —
/// the same scheme as [`Ascend`], with the same overlap-freedom: unifying two
/// impls would need a type that contains itself, which the occurs check
/// rejects, so no phantom index is needed. The nests bottom out at a generic
/// tail `T` rather than naming `&mut Root`; the ascent aliases pin `T` to the
/// root path, and the occurs check keeps even the bare-`T` terminal impls
/// disjoint from the `PathMut` ones.
pub trait Complete<A> {
    fn complete(self) -> A;
}

/// The ascent doll for a chain: `Doll<full path, Doll<next suffix, .. T>>`.
macro_rules! doll_nest {
    ($t:ident) => { $t };
    ($t:ident, $head:ident $(, $rest:ident)*) => {
        Doll<ascend_nest!($t, $head $(, $rest)*), doll_nest!($t $(, $rest)*)>
    };
}

/// One `Doll::Up` per peeled-past type parameter.
macro_rules! up_wrap {
    ($e:expr) => { $e };
    ($e:expr, $head:ident $(, $rest:ident)*) => {
        Doll::Up(up_wrap!($e $(, $rest)*))
    };
}

/// The `Complete` impls for ONE origin depth: focus at the origin, at each
/// ancestor, and at the bare tail.
macro_rules! complete_positions {
    // Focus peeled all the way to the tail: bare Up chain, no Here.
    ([$($done:ident),*], [], [$($all:ident),*]) => {
        impl<T, $($all,)*> Complete<doll_nest!(T $(, $all)*)> for T {
            fn complete(self) -> doll_nest!(T $(, $all)*) {
                up_wrap!(self $(, $done)*)
            }
        }
    };
    // Focus still on the chain: one Up per peeled layer, then Here.
    ([$($done:ident),*], [$lhead:ident $(, $lrest:ident)*], [$($all:ident),*]) => {
        impl<T, $($all,)*> Complete<doll_nest!(T $(, $all)*)> for ascend_nest!(T, $lhead $(, $lrest)*) {
            fn complete(self) -> doll_nest!(T $(, $all)*) {
                up_wrap!(Doll::Here(self) $(, $done)*)
            }
        }
        complete_positions!([$($done,)* $lhead], [$($lrest),*], [$($all),*]);
    };
}

/// One family of `Complete` impls per depth, walking the list of type
/// parameters exactly as `ascend_impls!` does.
macro_rules! complete_impls {
    ([$($acc:ident),*]) => {};
    ([$($acc:ident),*], $head:ident $(, $rest:ident)*) => {
        complete_positions!([], [$($acc,)* $head], [$($acc,)* $head]);
        complete_impls!([$($acc,)* $head] $(, $rest)*);
    };
}

complete_impls!([], N0, N1, N2, N3, N4, N5, N6, N7, N8, N9, N10, N11);
```

What the depth-2 family expands to, for reference:

```rust
impl<T, N0, N1> Complete<Doll<PathMut<N0, PathMut<N1, T>>, Doll<PathMut<N1, T>, T>>>
    for PathMut<N0, PathMut<N1, T>>
{
    fn complete(self) -> … { Doll::Here(self) }
}

impl<T, N0, N1> Complete<Doll<PathMut<N0, PathMut<N1, T>>, Doll<PathMut<N1, T>, T>>>
    for PathMut<N1, T>
{
    fn complete(self) -> … { Doll::Up(Doll::Here(self)) }
}

impl<T, N0, N1> Complete<Doll<PathMut<N0, PathMut<N1, T>>, Doll<PathMut<N1, T>, T>>>
    for T
{
    fn complete(self) -> … { Doll::Up(Doll::Up(self)) }
}
```

Depth d contributes d+1 impls; depths 1..12 give 90, generated once, covering every tree.

New function, beside `place_impl`:

```rust
/// Emits the node's ascent alias: the doll nest a leave from this node
/// completes into. The root gets none; nothing ascends from a root.
///
/// The body names only `<Self as Place>::Path`, so the derive needs no
/// ancestor's name: `laserbeam::AscentOf` computes the nest from the path
/// type. A node whose parent is a route enum gets the alias too; type aliases
/// are checked lazily, so it errors only where it is used, with "`Ascent` is
/// not implemented for `TheRouteEnum`".
fn ascent_alias(input: &DeriveInput, name: &Ident) -> TokenStream2 {
    if is_root(&input.attrs) {
        return quote!();
    }
    let vis = &input.vis;
    let alias = format_ident!("{name}Ascent");
    quote! {
        #vis type #alias<'a> = ::laserbeam::AscentOf<<#name as ::bind::Place>::Path<'a>>;
    }
}
```

Derived levels are untouched: `expand()` returns through `derived_node_impl` before reaching `place_impl`, so a level that is not a place emits no alias, matching it having no path.

## Consumers (before / after)

No consumer source changes. `bind/tests/common/mod.rs` and `mercury/src/state/*` keep their structs, attributes, and handwritten path aliases exactly as they are; the derive starts emitting, per non-root node, one ascent alias next to the existing impls:

```text
bind test tree:   LayerAscent, NavAscent, TypingAscent, DeepAscent,
                  ClashChildAscent, AlbumAscent, SongAscent, TitleAscent,
                  ArmedChildAscent
mercury:          LayerAscent, AppLayerAscent, SiteLayerAscent, …
```

`TitleAscent` (parent is the `TitleParent` route enum) is emitted and is unusable: any use fails with `Ascent is not implemented for TitleParent<'_>`. Multi-parent ascent is out, the same stance `Ascend` documents. Everything else resolves.

Both consumers already depend on laserbeam directly (the derive already emits `::laserbeam::PathMut` in `Place`), so the emitted `::laserbeam::AscentOf` resolves without a new dependency.

```rust
    let mut app = app_nav_tree(/* nav.hits = 7 */);
    let nav = nav_path(&mut app);

        panic!("expected Here, got other arm");

            1 => nav.into_parent().complete(),
```

## Rules

1. `Place::Path` only: `&mut Root` or `PathMut<Self, ParentPath>`.
2. `Ascent(root) = Path`; `Ascent(node) = Doll<Path, Ascent(parent)>`; `AscentOf` computes it; the derive emits `{Node}Ascent` per non-root place, nothing for roots or derived levels.
3. Peel is laserbeam `PathMut::into_parent` only; no wrapper type.
4. `complete` is `laserbeam::Complete<A>::complete`, impls only in laserbeam, keyed by path shape and depth; `A` pinned by the dispatch return type.
5. Child returns `Ascent(child)`; parent returns `Ascent(self)`; `Up` payload is `Ascent(self)`.
6. Root receives only the child-of-root ascent.
7. Over-peel past root, off-chain `complete`, and a route-parented node's ascent do not compile.
8. Arms: `Here` / `Up`. Path aliases stay handwritten.
